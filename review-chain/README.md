# review-chain: как пользоваться в Claude Code

Цепочка из четырёх ролей для проверки и исправления изменений в коде.

| Роль | Файл | Что делает | Пишет |
|------|------|-----------|-------|
| Великий сомневающийся | `.claude/agents/doubter.md` | Находит проблемы (до 15, с доказательствами) | `findings.md` |
| Несгибаемый арбитр | `.claude/agents/arbiter.md` | Проверяет находки, решает FIX или REJECT, пишет план | `plan.md` |
| Согласный производитель работ | `.claude/agents/producer.md` | Реализует план без вопросов | код, `report.md` |
| Всевидящий призрак | `.claude/agents/ghost.md` | Логирует и оценивает решения | `ghost-log.md` |

Оркестратор: `.claude/skills/review-chain/SKILL.md`. Он запускает роли по порядку как сабагентов.

## 1. Установка

Структура папки:

```
review-chain/
  README.md
  .claude/
    skills/review-chain/SKILL.md
    agents/
      doubter.md
      arbiter.md
      producer.md
      ghost.md
```

**В один проект.** Скопируйте папку `.claude/` в корень репозитория.

**Для всех проектов.** Скопируйте содержимое в домашнюю папку:

```
cp -r .claude/skills/review-chain ~/.claude/skills/
cp .claude/agents/*.md ~/.claude/agents/
```

Рекомендуется добавить `.review-chain/` в `.gitignore`: там лежат рабочие файлы цепочки.

## 2. Проверка, что всё подхватилось

1. Запустите (или перезапустите) Claude Code в корне проекта. Агенты читаются при старте сессии.
2. Введите `/agents`. В списке должны быть `doubter`, `arbiter`, `producer`, `ghost`.
3. Введите `/` и начните набирать `review`. Должна появиться команда `/review-chain`.

Если агентов нет в списке, перезапустите сессию.

## 3. Запуск

Скилл запускается вручную. В `SKILL.md` стоит `disable-model-invocation: true`, потому что цепочка тратит много токенов и Claude не должен включать её сам.

Примеры:

```
/review-chain
/review-chain проверь незакоммиченные изменения
/review-chain проверь ветку feature/payments относительно main
/review-chain проверь коммиты HEAD~3..HEAD
```

Цель изменения можно описать в той же строке. Если не описать, оркестратор возьмёт её из диффа и сообщений коммитов.

## 4. Что происходит дальше

1. Оркестратор сохраняет дифф в `.review-chain/change.diff` и цель в `goal.md`.
2. `doubter` пишет `findings.md`. Если нет находок уровня HIGH или MEDIUM, цепочка останавливается.
3. `arbiter` пишет `plan.md`: задачи FIX и список REJECT с доказательствами.
4. `producer` правит код и пишет `report.md`. Если план противоречит коду, он пишет BLOCKED и один вопрос.
5. `ghost` запускается после каждого этапа и дописывает `ghost-log.md`.
6. Опционально идёт второй раунд проверки. Раундов не больше двух.
7. В конце вы получаете короткую сводку.

Следите за рабочими файлами в `.review-chain/`. Самый интересный из них: `ghost-log.md`.

## 5. Настройка

- **Другая модель для роли.** Добавьте в frontmatter агента строку `model: opus` (или `sonnet`, `haiku`). Разные модели у `doubter` и `arbiter` дают больше независимости.
- **Лимит находок.** Измените число 15 в `doubter.md`.
- **Права инструментов.** Список `tools:` в каждом агенте задаёт, что роль может делать. Ограничение записи по конкретному файлу держится только на тексте промпта, поэтому оркестратор проверяет `git status` после каждого этапа.
- **Правила проекта.** Добавьте в `doubter.md` ссылку на ваш файл стандартов кода. Тогда замечания по стилю будут относиться только к нему.

## 6. Когда не стоит запускать

- Опечатка, переименование, правка в одну строку.
- Изменение, которое вы сами хорошо понимаете и можете проверить за минуту.

Цепочка нужна для нетривиальных изменений: PR, рефакторинг, новая функция, рискованное исправление.

## 7. Частые проблемы

| Симптом | Что делать |
|---------|-----------|
| `/review-chain` не видна | Проверьте путь `.claude/skills/review-chain/SKILL.md` и перезапустите сессию |
| Агент не найден | Проверьте `/agents`, имена в frontmatter и перезапустите сессию |
| Роль изменила лишние файлы | Оркестратор остановит цепочку. Уточните правила в файле роли |
| Слишком много мелких находок | Уменьшите лимит и усильте правило 5 в `doubter.md` |
| Арбитр отклоняет почти всё | Проверьте доказательства REJECT в `plan.md`. Они обязательны |
